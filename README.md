# Web Evidence Capture

Web Evidence Capture is a reusable tool for preserving public website state in a transparent, reproducible, forensic-style package.

It is technical preservation support, not legal advice. It does not guarantee admissibility, completeness, or legal sufficiency.

## Safety Model

The tool is designed for public-only capture:

- no authentication;
- no account creation;
- no form submission;
- no intentional access to private, admin, login, account, portal, or application paths;
- no direct contact with the target company outside ordinary public HTTP/browser page loads.

Runtime evidence is private by default. Case run folders are ignored by Git unless a user intentionally changes that policy.

## Quick Start

Install locally:

```bash
python3 -m pip install -e .
python3 -m playwright install chromium
```

Create a config:

```json
{
  "target_url": "https://example.org/",
  "case_slug": "example-org",
  "allowed_domains": ["example.org", "www.example.org"],
  "max_pages": 10,
  "cookie_choice": "none"
}
```

Initialize and run:

```bash
web-evidence init-case --config examples/minimal-config.json
web-evidence run --config examples/minimal-config.json
```

The output path is:

```text
cases/<case_slug>/runs/<YYYY-MM-DD-HHMM>/
```

## CLI Commands

- `web-evidence init-case`
- `web-evidence inventory`
- `web-evidence capture`
- `web-evidence render`
- `web-evidence privacy`
- `web-evidence singlefile`
- `web-evidence package-wacz`
- `web-evidence hash`
- `web-evidence validate`
- `web-evidence report`
- `web-evidence run`

Each command accepts either `--config <path>` or `--target-url` plus `--case-slug`. Use `--dry-run` to inspect intended behavior without network capture.

## GitHub Actions

The main workflow is manual. It captures from a GitHub-hosted runner, so observed content can differ by runner location, CDN routing, time, browser version, cookies, A/B testing, and network behavior.

Evidence generated by workflows is uploaded as private workflow artifacts in this private repository. No public report publication workflow is included in v1.

## Limitations

Website state is volatile. Dynamic scripts, consent state, geography, CDN behavior, personalization, rate limiting, and third-party services can change what is captured. Review generated reports, validation results, hashes, and logs before relying on a package.
