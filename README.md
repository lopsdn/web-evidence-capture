# Web Evidence Capture

Web Evidence Capture is a reusable tool for preserving public website state in a transparent, reproducible, forensic-style package.

It is technical preservation support, not legal advice. It does not guarantee admissibility, completeness, or legal sufficiency.

## Safety Model

The tool is designed for public-only capture:

- no authentication;
- no account creation;
- no form submission;
- no intentional access to private, admin, login, account, portal, or application paths;
- no direct contact with the target company outside ordinary public HTTP/browser page loads.

Local runtime evidence under `cases/` is private by default and ignored by Git. GitHub Actions captures are committed into reviewed snapshot folders so the source, workflow, logs, reports, manifests, hashes, and artifacts can be inspected together.

## Quick Start

Install locally:

```bash
python3 -m pip install -e .
python3 -m playwright install chromium
```

Create a config:

```json
{
  "target_url": "https://example.org/",
  "case_slug": "example-org",
  "allowed_domains": ["example.org", "www.example.org"],
  "max_pages": 10,
  "cookie_choice": "none"
}
```

Initialize and run:

```bash
web-evidence init-case --config examples/minimal-config.json
web-evidence run --config examples/minimal-config.json
```

The output path is:

```text
cases/<case_slug>/runs/<YYYY-MM-DD-HHMM>/
```

GitHub Actions snapshots are committed to:

```text
snapshots/<site>/<YYYY-MM-DD-HHMM>/
```

Each committed snapshot includes `START-HERE.md`, README files, reports, manifests, validation, hashes, logs, preserved artifacts, GitHub Actions run metadata/logs when available, a ZIP archive of the full snapshot, and a smaller website HTML ZIP for local browsing.

## CLI Commands

- `web-evidence init-case`
- `web-evidence inventory`
- `web-evidence capture`
- `web-evidence render`
- `web-evidence privacy`
- `web-evidence singlefile`
- `web-evidence package-wacz`
- `web-evidence hash`
- `web-evidence validate`
- `web-evidence report`
- `web-evidence run`

Each command accepts either `--config <path>` or `--target-url` plus `--case-slug`. Use `--dry-run` to inspect intended behavior without network capture.

## GitHub Actions

The main workflow is manual. It captures from a GitHub-hosted runner, so observed content can differ by runner location, CDN routing, time, browser version, cookies, A/B testing, and network behavior.

Evidence generated by workflows is uploaded as a workflow artifact and committed into `snapshots/`. The artifact is convenient for download, while the committed snapshot is the durable record after GitHub Actions run logs expire.

Inside a snapshot:

- Open `START-HERE.md` first.
- Open `report/report.md` for the complete report.
- Download `<site>-<run>-website-html.zip` to browse captured HTML locally.
- Download `<site>-<run>.zip` for the complete evidence package.

## Limitations

Website state is volatile. Dynamic scripts, consent state, geography, CDN behavior, personalization, rate limiting, and third-party services can change what is captured. Browser-observed cookies, storage state, headers, query values, request bodies, console events, and page errors may be preserved because they are part of the public runner session. Review generated reports, validation results, hashes, and logs before relying on a package.
